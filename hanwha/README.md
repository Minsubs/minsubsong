# KBO 티켓팅 도우미

KBO 10구단의 예매 오픈 일정, 예매처, 알림 저장 수요를 한 화면에서 검증하는 PWA입니다. 현재 목적은 상용화 전 무료 PWA로 실제 수요를 확인하고, 이후 취소표 관심 경기 알림까지 확장 가능한 제품 범위를 검증하는 것입니다.

## 제품 포지션

- 핵심 가치: 10구단 홈경기 예매 오픈 일정을 모아 보고, 예매 직전 알림을 저장한다.
- 현재 범위: 예매 일정 캘린더, 홈팀 기준 예매처 링크, 브라우저/PWA가 열려 있을 때의 티켓 알림, 로컬 수요 검증.
- 확장 후보: 사용자가 관심 경기를 저장하면 공식 예매처가 허용하는 방식으로 잔여석/취소표 상태 변화를 확인하고 알림을 주는 기능.
- 하지 않는 것: 자동예매, 대기열/안티봇 우회, 무단 스크래핑 기반 취소표 감시, 계정 로그인 대행.
- 수익화 가설: 제휴/굿즈 클릭, 광고 보조, 장기적으로 시즌패스 또는 네이티브 알림 확장.

## 실행

JSON 데이터를 fetch하므로 로컬 서버로 실행합니다.

```bash
python3 -m http.server 4173
```

브라우저에서 아래 주소를 엽니다.

```text
http://127.0.0.1:4173/index.html
```

또는 npm 스크립트를 사용할 수 있습니다.

```bash
npm run serve
```

## 주요 화면

- `실시간`: 경기판과 주요 랭킹
- `경기`: 최근/예정 경기
- `티켓팅`: 현재 노출 중인 경기의 티켓 정보
- `예매 캘린더`: 10구단 예매 오픈 캘린더와 구단 필터
- `랭킹`, `선수`: KBO/한화 데이터 확인
- `검증`: 알림 저장, 예매처 클릭, 구단 필터 선택을 로컬 집계

## 알림과 수요 검증

현재 티켓 알림은 브라우저/PWA가 열려 있을 때 30초 간격으로 저장된 알림 시간을 확인합니다. 앱이 완전히 종료된 상태의 백그라운드 푸시는 추후 네이티브 알림 또는 서버 푸시 연동이 필요합니다.

`검증` 탭은 `localStorage.eaglesDemandSignals`에만 신호를 저장합니다. 외부 전송은 없고, 필요할 때 JSON으로 내보낼 수 있습니다.

현재 기록하는 신호:

- `calendar_filter_selected`
- `provider_click`
- `ticket_reminder_saved`
- `notification_permission_result`
- `signals_exported`

취소표 관심 경기 알림은 아직 구현하지 않았습니다. 구현 전에는 예매처별 약관, robots/트래픽 정책, 로그인 필요 여부, 알림 빈도 제한, 제휴 가능성을 먼저 확인해야 합니다.

## 데이터

정적 데이터는 `data/` 폴더에 분리되어 있습니다.

- `data/meta.json`: 데이터 기준일, 안내문, 출처
- `data/summary.json`: 팀 요약
- `data/team-standings.json`: KBO 전체 팀 순위
- `data/live-game.json`: 메인 실시간 경기판
- `data/player-rankings.json`: 메인 선수 랭킹
- `data/games.json`: 한화 중심 경기 일정/결과
- `data/ticketing-calendar.json`: 10구단 예매 오픈 캘린더
- `data/players.json`: 선수 기록

데이터 연동 세부 내용은 `docs/DATA_INTEGRATION.md`에 정리되어 있습니다.

## 데이터 갱신

KBO 공식 페이지에서 팀 순위, 경기 일정, 선수 기록을 가져와 `data/*.json`을 갱신합니다.

```bash
npm run update:data
```

수집 원본 HTML/JSON은 `data/cache/raw/`에 저장되며 버전 관리에서는 제외됩니다.

## 검증

```bash
npm run check
```

현재 회귀 범위는 문법 검사, 데이터 파서/생성 테스트, PWA 등록/캐시/캘린더/검증 탭 정적 테스트를 포함합니다.

## 리스크와 휴먼게이트

- `ticketlink-macro/`는 제품 worktree 밖으로 분리했습니다. 현재 worktree에는 tracked deletion으로 남아 있으며 커밋 전입니다.
- 과거 git 히스토리에 macro 관련 커밋이 남아 있습니다. 히스토리 rewrite/force push는 위험 작업이므로 별도 승인 전에는 진행하지 않습니다.
- 과거 노출 가능성이 있는 계정 비밀번호는 사용자가 직접 교체해야 합니다.
- 상용화 카피는 현재 구현 기준으로 “공식 예매처 연결/알림 저장”까지만 허용합니다. 취소표 관련 카피는 공식 허용 방식 또는 제휴 데이터가 확보된 뒤 “관심 경기 상태 알림” 수준으로만 사용하고, “자동 구매/대기열 우회/무단 포착” 표현은 금지합니다.
