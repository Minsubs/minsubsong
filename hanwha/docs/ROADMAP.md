## 1. 개요 — 제품 테제

KBO 관중은 2024년 1,088만 → 2025년 1,231만으로 사상 최대, 매진율 45.7%로 급증 중인데 [FMR §3], **"10구단 예매 오픈을 한 곳에서, iOS 포함 신뢰성 있는 푸시로 안 놓치게"** 해주는 곳이 사실상 없다 — 직관메이트는 Android 단독, 공식 앱은 평점 2.1, 예매처는 "취소 발생 후" 대기만 한다 [FMR §2.2].

> **메리트 = (갭) 비어 있는 iOS·PWA + 통합 캘린더 + 신뢰성 있는 사전 푸시 × (수요) 구조적으로 커지는 티켓팅 페인 × (차별점) 거래를 하지 않고 "알림·정보 레이어"만 제공.**

거래를 안 하는 포지션은 2026-08-28 시행 개정 암표법 강화 속에서 오히려 안전성이 높아지며 [FMR §4][MR0707 §4], 자동예매·잔여석 자동감시·로그인대행·무단스크래핑을 일절 하지 않는 원칙은 윤리이자 법적 필수 요건이다 [CTA §3.1]. 진짜 무기는 한 줄로 **"앱이 닫혀 있어도 오는 예매 오픈 임박 푸시"**이고, 이를 구현하는 표준 메커니즘이 Web Push다 [BPP §1.1].

**불변 원칙(절대):** 자동예매·매크로 금지 · 잔여석 자동감시/폴링 금지 · 대기열/안티봇 우회 금지 · 무단스크래핑 감시 금지 · 로그인대행 금지 · 개인정보 최소화 · 광고성 푸시 금지(어필리에이트는 화면 내·푸시와 분리).

### 4.2 알림 온보딩 UX ([BPP §3·§4] 정합)

**3단계 soft-prompt(가치 먼저 → 권한):** 첫 진입 즉시 권한 요청 금지 [BPP §3.3]. 자연 트리거는 티켓 리마인더/취소표 관심 저장 직후.

- **Step A 가치 카드**: "예매 오픈 1시간 전, 앱이 꺼져 있어도 푸시로 알려드려요" — 카테고리 미리보기 + CTA "알림 받기".
- **Step B 권한**: 사용자 제스처 안에서 `Notification.requestPermission()`. 거부 시 복구 비용 안내(iOS 1회/Android 2회 [BPP §3.1]).
- **Step C 구독 등록**: granted 후 `pushManager.subscribe` + 백엔드 POST [BPP §6 #3] — 이 플랜은 UI만, 실제 구독은 X0 구현.

**iOS "홈 화면 추가" 설치 가이드:** iOS는 standalone PWA에서만 푸시 가능 + 자동 프롬프트 없음 [BPP §3.1-3.2]. 권한 prompt **이전**에 설치 단계 선행 — Safari 감지 → 미설치 시 "공유 → 홈 화면에 추가" 3스텝 SVG 일러스트 시트(`navigator.standalone`/`display-mode: standalone` 미충족 시). 알림센터 상단에 설치됨/미설치 상태칩 상시 표기.

**카테고리별 opt-in(전부 기본 OFF):** 단일 "알림 허용?" 금지. 토글 = `ticket_open`(예매 오픈)/`cancel_window`(취소표 타임)/`weather_cancel`(우천취소)/`game_result`(결과). 부가: 야간 예매 알림 예외 토글, 조용한 시간 22:00–08:00 안내, "끄면 서버 기록도 즉시 삭제" 고지 + 전체 끄기(unsubscribe+DELETE) [BPP §4.2]. 빈/오류: denied → "OS 설정에서 켜기" 카드, 미지원 → 비활성+사유. 기존 `eaglesNotifications` 단일 플래그 → `topics` 객체 확장(마이그레이션 방어) **[J]**.
